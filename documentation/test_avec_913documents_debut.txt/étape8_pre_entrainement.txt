Pourquoi gradient_clip: 1.0 ?

On limite la norme des gradients :

torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    1.0
)

Cela permet d'éviter qu'un gradient extrêmement grand provoque une mise à jour trop importante.

Pourquoi eval_every: 20 ?

Ton entraînement est très court :

≈ 189 steps

Si on évaluait seulement à chaque epoch, on aurait seulement 3 évaluations.

Avec :

eval_every: 20

on peut suivre l'évolution beaucoup plus précisément :

step 20
step 40
step 60
step 80
...
step 180
Pourquoi save_every: 50 ?

On aura environ :

step 50
step 100
step 150
step 189

Donc quelques checkpoints raisonnables sans en créer des dizaines.

3-calcul approximatif du nombre de paramètres du Student

        A. Configuration du Student

            Nous avons :

            vocab_size   = 16 000
            d_model      = 256
            num_heads    = 8
            num_layers   = 4
            d_ff         = 1 024
            max_seq_len  = 256

            Avec :

            head_dim = 256 / 8 = 32

        B. Token Embedding

            Ton vocabulaire contient :

            16 000 tokens

            Chaque token est représenté par un vecteur de :

            256 dimensions

            Donc :

            16 000 × 256
            = 4 096 000

            ➡️ 4,096 millions de paramètres

        C. Positional Embedding

            Comme nous avons choisi des learned positional embeddings :

            max_seq_len = 256
            d_model = 256

            Donc :

            256 × 256
            = 65 536

            ➡️ 65 536 paramètres

        D. Un Transformer Block

            Nous avons 4 Transformer Blocks.

            Chaque block contient principalement :

            Multi-Head Self-Attention
                    +
            Feed Forward
                    +
            LayerNorm

            Calculons-les.

        D.1 Attention

            Avec :

            d_model = 256

            on utilise généralement quatre projections :

            Q
            K
            V
            O

            Chacune est une matrice :

            256 × 256

            Donc :

            Q = 65 536
            K = 65 536
            V = 65 536
            O = 65 536

            Total poids :

            4 × 65 536
            = 262 144

        D.2-Les biais éventuels ajoutent :

            4 × 256
            = 1 024

            Donc environ :

            263 168

            ➡️ ~263 K paramètres pour l'attention

        E. Feed Forward Network

            Ton FFN est :

            256 → 1024 → 256

            Première projection :

            256 × 1024
            = 262 144

            Deuxième :

            1024 × 256
            = 262 144

            Poids :

            524 288

            Biais :

            1024 + 256
            = 1 280

            Total :

            525 568

            ➡️ ~526 K paramètres

        F. LayerNorm

            Avec le Pre-LN, nous avons généralement deux LayerNorm par Transformer Block :

            LayerNorm 1
            LayerNorm 2

            Chaque LayerNorm possède :

            gamma = 256
            beta  = 256

            Donc :

            512 paramètres

            par LayerNorm.

            Deux :

            512 × 2
            = 1 024

            ➡️ 1 024 paramètres

        G. Total d'un Transformer Block

            On additionne :

            Attention       ≈ 263 168
            FFN             ≈ 525 568
            LayerNorm       =   1 024
            --------------------------------
            Total            ≈ 789 760

            Donc environ :

            790 000 paramètres par block.

        H. Les 4 Transformer Blocks

            Nous avons :

            num_layers = 4

            Donc :

            789 760 × 4
            = 3 159 040

            ➡️ ~3,16 millions de paramètres

        I. Final LayerNorm

            Après les Transformer Blocks, nous avons notre LayerNorm final :

            256 × 2
            = 512

            ➡️ 512 paramètres

        J. LM Head

            Le modèle doit transformer les représentations de dimension 256 en probabilités sur les 16 000 tokens.

            Donc :

            256 → 16 000

            Poids :

            256 × 16 000
            = 4 096 000

            Avec un biais :

            + 16 000

            Donc :

            4 112 000

            ➡️ ~4,112 millions

        K. Total

            Additionnons :

            Token Embedding       4 096 000
            Positional Embedding     65 536
            Transformer ×4        3 159 040
            Final LayerNorm             512
            LM Head               4 112 000
            --------------------------------
            TOTAL                11 433 088

            Donc ton Student possède environ :

            11,43 millions de paramètres
            12. Attention au weight tying

            Il existe une optimisation importante pour ton modèle.

            On peut partager les poids entre :

            Token Embedding

            et :

            LM Head

            Au lieu d'avoir :

            Embedding = 4 096 000
            LM Head   = 4 096 000

            on utilise la même matrice.

            Dans ce cas, on économise environ :

            4 096 000 paramètres

            Ton modèle passerait approximativement de :

            11,43 M

            à :

            ≈ 7,34 M paramètres

            C'est une technique courante appelée weight tying.

4-choix de batch_size / sequence_length


    1. Tes paramètres actuels

        On part de :

        vocab_size   = 16 000
        d_model      = 256
        num_heads    = 8
        num_layers   = 4
        d_ff         = 1 024

        Et ton dataset tokenisé :

        Train       = 2 009 séquences
        Validation  =   282 séquences

        Chaque séquence contient actuellement :

        256 tokens
        2. sequence_length = 256

        Je garderais 256 pour l'étape 8.

        Cela signifie que ton Transformer peut traiter :

        [token₁, token₂, ..., token₂₅₆]

        en une seule séquence.

        Son contexte maximal est donc :

        256 tokens.

        Pourquoi 256 ?

        Ton modèle est petit :

        ≈ 11,4 M paramètres

        et ton dataset est également petit.

        Passer directement à :

        512
        1024
        2048

        augmenterait fortement le coût de l'attention.

        L'attention a approximativement une complexité en :

        O(sequence_length²)

        Donc :

        256² = 65 536
        512² = 262 144
        1024² = 1 048 576

        Ainsi, passer de 256 à 512 multiplie approximativement le travail de l'attention par 4.

        Pour ton premier pré-entraînement, 256 est donc un choix raisonnable.

    3. batch_size = 32

        Avec :

        batch_size: 32
        sequence_length: 256

        un batch contient :

        32 × 256
        = 8 192 tokens

        Donc à chaque step, ton modèle traite environ :

        8 192 tokens.

        Visuellement :

                        Batch
                        │
            ┌───────────┼───────────┐
            │           │           │
            ▼           ▼           ▼
            Seq 1       Seq 2       Seq 3 ...
            256 tok     256 tok     256 tok
            │           │
            └───────────┴───────────┘
                        │
                        ▼
                    32 séquences
                        │
                        ▼
                    8 192 tokens
    4. Est-ce que 32 est adapté à Colab ?

        Pour ton modèle de seulement ~11,4 M paramètres, 32 devrait être une bonne valeur de départ sur un GPU Colab, sous réserve de la mémoire réellement disponible.

        Mais il ne faut pas supposer que la mémoire nécessaire dépend uniquement des paramètres du modèle.

        Pendant l'entraînement, le GPU doit également conserver :

        Modèle
        + gradients
        + états AdamW
        + activations
        + batch

        Les activations deviennent notamment plus importantes lorsque :

        batch_size ↑
        sequence_length ↑

        C'est pourquoi on teste réellement la configuration sur le GPU.

    5. Ton dataset avec batch_size = 32

        Tu as :

        2 009 séquences

        Avec :

        batch_size = 32

        on obtient :

        2009 / 32 = 62,78

        Donc :

        62 batches complets
        + 1 batch partiel

        soit 63 steps par epoch si drop_last=False.

        Je recommande :

        DataLoader(
            dataset,
            batch_size=32,
            shuffle=True,
            drop_last=False
        )

        Ainsi tu ne jettes pas les dernières données.

    6. Nombre de tokens par epoch

        Chaque epoch voit :

        2 009 × 256

        soit :

        514 304 tokens

        Le batch_size ne change pas cette quantité.

        Il change seulement combien de tokens sont traités simultanément.

        batch_size = 16
        → 4 096 tokens / step

        batch_size = 32
        → 8 192 tokens / step

        batch_size = 64
        → 16 384 tokens / step


    7. Comparaison

        Configuration	Tokens / step	Steps / epoch	Attention
        16 × 256	4 096	~126	faible
        32 × 256	8 192	~63	raisonnable
        64 × 256	16 384	~32	plus de mémoire
        32 × 512	16 384	~63*	~4× coût attention

        * Si les données étaient également organisées en séquences de 512 tokens.

        Pour ton premier entraînement, je partirais donc sur :

        batch_size: 32

        et :

        max_seq_len: 256

    8. Un détail important : max_seq_len ≠ forcément sequence_length

        Dans ton architecture, tu as :

        max_seq_len: 256

        Cela signifie que ton modèle accepte au maximum 256 tokens.

        Ton Dataset peut donc produire :

        [256 tokens]

        et le modèle fonctionne avec cette longueur.

        Dans notre configuration actuelle, on peut simplement avoir :

        sequence_length = max_seq_len = 256

        Mais conceptuellement :

        max_seq_len
            │
            └── capacité maximale du Transformer

        sequence_length
            │
            └── longueur réellement utilisée par le Dataset

        Pour l'étape 8, je recommande de les garder identiques.

    9. Configuration finale recommandée

        Dans model.yaml :

        vocab_size: 16000

        d_model: 256
        num_heads: 8
        num_layers: 4
        d_ff: 1024

        max_seq_len: 256

        dropout: 0.1

        Dans training.yaml :

        batch_size: 32
